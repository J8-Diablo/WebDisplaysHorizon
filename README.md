# WebDisplays for Horizon

Web browsers on screens in the world: a rewrite in Rust, for Horizon, of the
[WebDisplays](https://github.com/J8-Diablo/webdisplays) mod. Windows x64 only for now, and
still in development.

## What is in it

- Screens made of blocks, and traced screens (drawn with the stylus, with rounded corners)
  that show a web page.
- Keyboard, remote control, redstone controller, linking tool, configurator, laser pointer,
  MinePad.
- Linked screens (one page over several screens) and shared browsers.
- Sound that follows the place (echo in a room, muffled behind a wall), and speakers
  (tweeter, bass, full range).
- Light from the screens on what is around them.
- YouTube and Twitch addresses open as full-frame players, live streams included.

## It needs HCEF

The browser is another mod's: [HCEF](https://github.com/J8-Diablo/HCEF). The native mod
declares it (`[dependencies] hcef = "^0.1"` in `native/horizon-mixin.toml`), and the
launcher refuses to build WebDisplays without it:

```
error: webdisplays_native requires missing mod hcef
```

Install HCEF first, build both, then download the browser once from Options > Mods > HCEF
in the game.

## One file

The mod is one file to install, `webdisplays_native.hnmod`. Its blocks, items, recipes,
textures, sounds and translations are a content mod that rides inside the native mod
(`native/data/webdisplays-content.hmod`): the helper `native/embedded_content.rs` hands it to
the game's own loader of content mods, as a development mod. `tools/pack.py` writes that
file from `content/`; it is committed because a build from this folder compiles it in.

`webdisplays.hmod` alone is still packed, for an instance that wants the content apart: an
installed copy that is turned on is read first.

## Repository

| Folder | What |
|---|---|
| `content/` | the content mod (`webdisplays`): blocks, items, recipes, languages. Generated by `tools/mkcontent.py` from the Java mod's resources, never edited by hand |
| `native/` | the native mod (`webdisplays_native`): everything the mod does, and the content mod in `data/` |
| `tools/` | content generator, checks, pack and test scripts |
| `registry/` | the page and icon for Horizon's mod registry |

## Building

The tools expect HCEF's repository beside this one (`../HCEF`, or `HCEF_REPO`).

```sh
tools/check.sh                   # type-checks the mod against the pinned Horizon source
cargo test --manifest-path tools/dev-logic/Cargo.toml   # the mod's logic, outside the game
python -I tools/mkcontent.py <WebDisplays Java repo>     # regenerates content/
python -I tools/check_content.py
python -I tools/pack.py          # dist/webdisplays.hmod and dist/webdisplays_native.hnmod
tools/dev.sh build               # compiles HCEF and WebDisplays into a development instance
```

After a change to `content/`, run `tools/pack.py` before building: the native mod compiles in
the copy in `native/data/`.

## License and credits

MIT (`LICENSE`). A rewrite of WebDisplays, the mod by
[montoyo](https://github.com/montoyo/webdisplays) (public domain) continued by the
[CinemaMod Group](https://github.com/CinemaMod/webdisplays) (MIT): the textures, models,
sounds and translations come from it.

The sound model (`native/api/src/acoustics/`) follows the method of
[Sound Physics Remastered](https://github.com/henkelmax/sound-physics-remastered) (rays,
occlusion, shared airspace) and uses its default reflectivity and occlusion numbers; it is
written anew in Rust, and the length of the echo is worked out differently.
